# 3.6 数据工程与治理

训练结果是否可信，不只取决于模型和训练框架，也取决于“训练到底用了哪份数据、数据是否完整和合规、处理过程是否可重现”。当前数据主要以共享目录、脚本和人工约定的方式流转，目录可能被覆盖，处理规则可能没有留痕，数据质量问题往往要到训练数小时后甚至模型交付时才被发现。出现异常时，团队很难回答数据从哪里来、谁批准使用、经过了哪些处理，以及还有哪些任务和模型受到影响。

因此，数据工程与治理模块需要把分散在目录和脚本中的数据，转变为可登记、可验证、可授权、可复现和可追溯的数据版本。平台不负责从外部环境下载或搬运数据，而是在已有网络盘范围内完成登记、检查、引用和影响分析，为训练、评测、审批和交付提供统一的数据依据。

## 3.6.1 数据集登记与不可变版本

### 背景介绍

训练任务通常只填写一个共享目录路径，但目录里的文件可能被覆盖、缺少分片、仍在拷贝，或被不同人员用脚本重新处理。路径没有版本和内容摘要，用户就无法确认本次训练实际使用了哪些文件；同一个任务下次再运行时，目录内容可能已经变化，导致结果无法复现。由于平台只引用已经落盘的网络盘数据，不负责从外部环境下载或补齐文件，更需要在登记和提交前明确数据是否完整、可读、稳定以及由谁负责。因此，数据集登记不是简单保存一个路径，而是为后续训练和审计建立不可变的数据版本。

### 建设目标

登记名称、逻辑版本、网络盘路径、文件清单、数量、大小、内容哈希、格式、分词器、样本与`token`量、放置人和时间。登记与提交时检查目录存在、可读、非空且清单稳定，未落盘数据不可选择。

|信息类别|必须记录的内容|主要用途|
|---|---|---|
|逻辑标识|数据集名称、不可变版本、项目和责任人|稳定引用和责任定位|
|物理位置|`/share/...`或`/data/hpc/home/<user>/...`|运行前验证目录存在与权限|
|文件清单|文件名、大小、分片、内容哈希和生成时间|识别覆盖、缺失和损坏|
|数据协议|格式、字段、消息协议、分词器和模板|选择解析器并保证语义一致|
|处理信息|脚本提交号、过滤与脱敏规则、随机种子|重建处理过程|
|统计摘要|样本数、`token`量、长度、语言、标签和重复率|估算资源并识别异常|
|授权信息|来源、许可证、用途、地域、保留期和审批证据|提交和交付前策略判定|

### 建议方案

数据模块维护不可变`DatasetVersion`和`manifest`，物理文件继续位于现有网络盘；大目录清单由异步扫描任务生成并增量校验。任务模块只保存`dataset`引用和提交时摘要，不复制数据模块内部实体，也不提供下载或同步后端。

## 3.6.2 安全预览与只读访问

### 背景介绍

训练前，算法人员需要先确认样本字段、角色关系、答案内容和模板效果是否符合预期，但只看目录名或文件数量无法发现这些问题。直接下载原文虽然方便，却会扩大敏感数据的传播范围；训练脚本如果没有只读约束，还可能把中间结果写回输入目录，污染其他任务继续使用的数据。平台需要提供受权限控制的脱敏预览和只读引用，让用户在不复制、不外发、不修改原始数据的前提下完成训练前确认。

### 建设目标

提供受权限控制的抽样预览、字段统计、模板渲染示例和默认脱敏展示；数据按团队、项目和用途授权，任务只读挂载输入，输出目录按用户或项目隔离并记录访问主体。

### 建议方案

预览由受限采样任务生成脱敏快照，接口不直接读取任意用户路径；挂载策略由任务运行适配器执行只读约束。预览与下载权限分离，原文访问写入审计日志并设置分页和数量上限。

## 3.6.3 数据质量、安全与去重

### 背景介绍

数据问题很多不会在任务启动时立即报错：编码或字段错误可能让样本被静默跳过，异常长度会增加截断和显存压力，重复数据会放大某些样本，训练集与评测集相似还会造成虚高分；密钥、个人信息和违规内容则可能在训练数小时后或模型交付前才被发现。等问题暴露时，算力已经消耗，模型结果也可能已经被他人引用。因此，平台需要在数据进入训练前分层检查结构、统计分布、重复泄漏和安全风险，并明确哪些问题必须阻断、哪些问题可以带风险继续。

### 建设目标

分层执行编码、格式、空值、长度、语言、`token`分布、精确与近似去重、敏感信息和违规内容检查。报告区分阻断项和统计项，保存规则版本、阈值、数量及可追溯样本`ID`；严重问题隔离并禁用数据版本。

数据检查按成本和风险分层执行：

|检查层级|范围与执行方式|结果与处理|
|---|---|---|
|快速结构检查|同步检查编码、格式、必填字段、空值和文件清单|确定性错误直接阻断登记或提交，并返回样本`ID`|
|统计质量检查|异步统计长度、语言、`token`分布、异常值和截断风险|生成版本化报告；超阈值时警告或阻断|
|重复与泄漏检查|异步执行样本`ID`、精确内容和近似相似度比对|输出命中清单摘要，支持隔离、去重和评测污染判定|
|语义与安全检查|异步识别敏感信息、违规内容和高风险样本|原文最小权限展示；严重问题禁用数据版本并通知责任人|

### 建议方案

快速规则同步运行，统计、近似去重和语义安全检查以普通批任务异步执行；只有规模和容错需要时再引入`Ray`、`Data-Juicer`或`NeMo Curator`。结果按分区写入，列表和报告读取聚合快照，不在页面请求中扫描样本。

## 3.6.4 授权与可复现处理

### 背景介绍

数据能读到，并不等于可以放心用于训练或模型交付。数据可能只允许特定项目、用途或地域使用，训练人员有读取权限也不代表已经获得评测和交付授权；如果同一目录被不同脚本、过滤规则、分词器或随机种子处理，最终有效数据分布也会不同。没有授权证据和处理参数记录，平台无法在提交时阻止违规使用，也无法在结果异常时重建当时的数据版本。因此，需要把“能不能用”和“怎样处理过”一起登记并纳入任务提交检查。

### 建设目标

记录来源、许可证、用途和地域限制、保留期限、责任人、审批证据，以及预处理脚本提交号、过滤规则、分词器、随机种子和统计报告。任务提交时执行用途策略检查。

### 建议方案

授权策略由数据模块拥有并向任务和交付模块提供批量判定契约；处理运行输出新数据版本和血缘边，不覆盖原版本。策略不可用时，正式训练与交付采取拒绝策略，普通元数据浏览可降级为脱敏结果。

## 3.6.5 数据血缘

### 背景介绍

数据问题往往不是在数据登记时才发生：模型效果异常、数据授权撤销、敏感样本被要求删除，或者某个处理脚本被发现有缺陷时，团队需要知道哪些处理任务、训练运行、评测报告和已交付模型使用了这份数据。当前数据、任务、训练产物和模型资产系统记录分散，通常只能靠人工回忆或全文搜索，既容易漏掉受影响对象，也无法快速判断是否需要停止交付或重新训练。因此，训练平台需要维护从原始数据到交付记录的可追溯关系，并把血缘摘要随模型产物提交给模型资产系统。

### 建设目标

记录原始目录、数据版本、处理任务、过滤和脱敏规则、`mixture`、训练运行、评测运行、训练产物和交付记录之间的有向关系，并关联模型资产系统返回的正式资产标识，支持正向追踪和反向影响分析。

数据从登记到模型交付的主要血缘关系如下：

```mermaid
flowchart LR
    raw["原始目录与文件清单"] --> process["处理任务<br/>脚本、规则与随机种子"]
    process --> dataset["不可变数据版本"]
    dataset --> mixture["混合与采样版本"]
    dataset -->|"直接使用"| train["训练运行"]
    mixture --> train
    train --> artifact["训练产物"]
    dataset --> eval["评测运行"]
    artifact --> eval
    eval --> report["评测报告与门禁证据"]
    artifact --> delivery["模型交付记录"]
    report --> delivery
    delivery --> asset["模型资产系统资产标识"]
```

### 建议方案

优先使用关系表和有界深度查询承载当前规模，不预先引入图数据库；各模块在对象创建时发布版本引用事件，由训练侧血缘投影维护到交付记录的关系。模型资产系统接收后的资产血缘由该系统维护，训练平台只保存返回的资产标识和交付回执。图谱查询分页返回投影对象，并限制节点和深度，避免跨模块递归详情调用。

## 3.6.6 数据混合与采样

### 背景介绍

预训练和后训练经常需要把多份数据混在一起使用，但“用了哪些目录”并不能说明实际训练分布。相同的数据集如果权重、采样温度、样本上限或重复轮数不同，模型看到的样本比例就会不同，训练时长、有效`token`量和最终能力也会随之变化。若平台只保存目录列表，后续既无法解释两个模型为什么不同，也无法准确复现一次训练。因此，混合与采样策略需要作为独立、不可变的版本保存，而不是隐藏在启动命令或脚本参数中。

### 建设目标

将多数据集组成不可变`mixture`版本，记录每个输入版本、权重、采样策略、温度、上限、重复轮数、计划与实际采样量及有效`token`占比。

### 建议方案

`mixture`是引用数据版本的轻量对象，采样清单由数据处理任务生成；任务规格引用其版本和内容摘要。聚合统计在生成阶段一次计算，详情批量读取成员摘要，避免逐数据集查询。

## 3.6.7 偏好、标注与合成数据

本能力只在监督微调、偏好优化或强化学习后训练模块启用时生效；相关模块未启用时隐藏入口，不影响预训练数据治理链路。

### 背景介绍

偏好、标注和合成数据会直接决定后训练优化的方向和评测结论，但它们比普通语料更依赖过程信息。正负样本顺序或拒答关系写反，可能让优化方向完全相反；标注指南、标注批次和抽检标准变化，会让不同批次的质量不可比较；合成数据使用的模型、提示词和过滤规则变化，也可能把生成偏差或评测污染误认为模型能力提升。若只保存最终文件，不记录这些来源和过程，出现效果变化时就无法判断是模型改动还是数据过程改动。因此，需要把偏好协议、标注过程和合成来源作为可审计的数据版本管理。

### 建设目标

统一偏好对、排序列表、拒答和多候选协议，校验`prompt`、`chosen`和`rejected`关系；登记标注任务、批次、标注者、指南、冲突率、抽检结果，以及生成模型、提示词、采样、过滤、去重和人工审核信息。

### 建议方案

通过数据适配器接入既有标注或反馈系统，不自研完整标注平台；导入后生成不可变数据版本和质量报告。偏好与合成来源作为样本级或分片级元数据保存，统计接口读取预聚合占比。

## 3.6.8 数据漂移分析

### 背景介绍

业务数据会持续增加、更新和变化，新的数据可能在语言比例、长度、业务标签、质量或重复率上与历史数据明显不同。数据分布变化后，过去验证过的模板、资源估算和训练参数可能不再合适，历史评测结论也可能不能代表当前数据；如果等到训练失败或线上反馈变差才发现，定位原因和回滚成本都很高。平台需要比较相邻数据版本的变化，说明变化是否超过阈值、可能影响哪些任务和模型，并把结果作为重新校验训练方案的依据。

### 建设目标

比较连续数据版本的样本量、语言、标签、长度、质量和重复率分布，展示变化幅度、阈值原因和受影响的模板、任务或模型。

### 建议方案

复用数据版本已有统计快照计算差异，不重复扫描原始数据；漂移规则异步执行并写入事件。影响对象通过血缘批量查询，阈值由团队维护并保留版本。
