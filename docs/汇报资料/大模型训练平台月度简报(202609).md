# 大模型训练平台月度简报(202609)

# 第一部分：核心方向进展大盘（看现状）

## 项目背景

原有大模型训练系统采用开源方案，能够支持短时训练任务，但在大规模预训练等长周期任务中稳定性不足；同时，开源社区活跃度有限，故障处置较多依赖运维人员手动排查，定位与恢复效率较低。2025年12月至2026年8月，`AIHPC`集群累计记录`111`起故障，其中`GPU`硬件故障`82`起，占`73.88%`，`IB`网络故障`13`起，占`11.71%`，且2026年7月至8月故障量明显处于高位。随着训练任务规模扩大、运行周期延长，亟需建设面向长周期训练的稳定调度、统一可观测和故障闭环能力。

## 核心目标、交付进展与资源投入

**核心目标**：总体目标是提高大模型长周期训练的稳定性，缩短训练中断与排障时间，并降低平台长期维护成本。第三季度聚焦建设`MVP`版本，优先解决长周期训练稳定性不足、运行状态缺少统一观测、故障依赖人工排查等核心痛点，并在`SLM`项目中进行小规模投产验证。

|**重点方向**|**本季度交付**|**阶段价值**|**状态**|
|---|---|---|---|
|**训推一体与训练管理**|落地`K8S + Volcano`训练链路，打通任务、队列、配置、日志和告警|训推复用基线、调度、监控和运维体系，避免双技术栈重复建设|一期完成，真实集群验证中|
|**可观测数据中心与故障保障**|完成统一可观测数据中心一期建设，按训练任务关联指标、日志、事件和`FastX`告警，形成故障节点隔离、修复和重新入池闭环|从分散排查转为任务级全链路分析，提升定位和协同处置效率|一期完成，持续优化真实样本|
|**平台治理**|完成用户、团队、角色、集群、节点和队列管理|为资源配额、优先级、审计和利用率分析建立基础|基础能力完成|

**资源投入**：Q3投入`3`名研发和`1`名测试，郭强担任项目及研发主要负责人，薛童协同`AI-HPC`故障分析和保障机制；后续保持`3`名研发持续迭代维护。上线初期复用`SLM`已有`16`台`H200`服务器及配套`IB`网络，无需新增硬件采购。

## 核心能力与价值看板

本季度已完成训推一体云原生底座、统一可观测数据中心和训练故障归因能力的一期建设，形成任务提交、运行监控、故障定位和资源恢复闭环。训练与推理采用了统一的技术底座，降低长期技术复杂度和维护成本；建设完成可观测数据中心，统一汇聚指标、日志、事件并接入告警，支撑任务级全链路监控与分析，提高故障发现的全面性和定位效率。

# 第三部分：核心策略与具体行动计划（谋出路）

## 下阶段重点工作安排

下阶段将围绕算法研发提效、训练稳定性提升和运维智能化三条主线推进以下工作。其中，后训练编排当前业务规模较小，作为后置储备方向。

|**重点工作**|**背景与必要性**|**实现目标**|**业务改善**|
|---|---|---|---|
|**实验管理与分析闭环**|实验配置、指标和产物分散，对比与复现依赖人工整理|关联实验、`Run`与任务，归集配置、指标和产物，支持`TensorBoard`及`Run`对比|缩短实验筛选与复盘周期，提高结果复现和经验复用效率|
|**故障检测规则持续迭代**|故障类型和表现多样，现有规则需结合真实样本校准|建立版本化规则库和复盘机制，持续优化检测信号、阈值和优先级|提前发现并隔离故障资源，减少误报、漏报和人工排查|
|**开发机标准化管理**|开发与训练环境不一致，且空闲开发机容易长期占用资源|统一镜像、规格、路径、权限和生命周期，支持一键转训练及空闲回收|降低环境漂移导致的失败，减少环境准备时间并提高`GPU`利用率|
|**高阶故障恢复能力**|故障后仍需人工校验`checkpoint`并重提任务，夜间中断恢复不及时|建立`checkpoint`管理和完整性校验，在重试与人工接管约束下实现自动恢复|减少训练进度丢失和无人值守等待，提高长周期训练有效运行时长|
|**后训练编排系统优化**|当前业务规模较小，短期对完整编排能力的需求有限|优先梳理流程和基础规范，保留模板与编排扩展能力，根据业务增长逐步建设|控制当期投入并避免过早建设，为后续业务扩展保留基础|
|**`AI Native`智能化运维升级**|告警、指标、日志和事件分散，人工关联证据难以支撑规模化运维|引入`AI Agent`聚合故障证据并生成排查建议，高风险动作保留人工确认和审计|缩短告警理解和初步定位时间，推动运维知识沉淀与智能辅助处置|
