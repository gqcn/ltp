
# 需求背景

当前模型训练平台基于`OpenSCOW`开源项目搭建，底层资源管理和调度使用`Slurm`实现，产品代号`ai-hpc`，但目前该基础设置技术栈比较老，长时间没有继续迭代。随着公司的`SLM`预训练项目的开展，所需要的资源和集群都比较大，因此我们考虑基于主流的云原生技术栈重构训练平台，以满足预训练和未来后训练的业务需求。随后逐步替换掉老的`ai-hpc`平台。

在Q3w我们需要实现一个训练平台的MVP版本，主要满足预训练的需求，以下是一些初步的想法：
1. 在SLM一个集群上（目前有4个集群：15 B300，30+H100，128 H100,16 H200）替换落地，对比ai-hpc可能优势：监控告警覆盖度更高、故障自愈、实验管理。研发需要重度使用ai coding，一些基础组件选型可参考下面
    - 实验管理：swanlab local模式
    - 资源管理调度：优先考虑k8s+volcano+ray，但是如果复杂度过高，那么也可以保持现有的slurm
    - 框架集成：megatron、nemotron（预训练）、ms-swift（微调）、verl（RL）、evalscope（评测）?
    - 数据加速层：juicefs？
2. 目前实验管理算法使用的 swanlab ，使用local模式
3. 框架集成 通过基于volcanno 或者 基于argo-workflow 编排也行。 预置 + 自定义
4. ray不一定引入，ray 用在数据处理上比较多
5. 业务目标是：
    - 预训练：先满足
    - 后训练：这个工具链更加复杂，训练 推理都涉及。
6. 优先考虑基于成熟的开源项目进行集成或者二次开发。
