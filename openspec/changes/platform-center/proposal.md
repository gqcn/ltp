## Why

数据中心闭环已经可用，但登录页的`LDAP`入口仍被拦住，侧栏也不展示平台中心。原型中的用户、团队、角色与系统配置是后续训练/运维权限的前提，需要在本迭代接上真实`LDAP`（本地用 Docker 模拟）并把平台中心做成可验收闭环。

## What Changes

- 登录页「LDAP 用户」改为真实认证：账号必须已加入平台可用用户且启用，密码走`LDAP bind`；平台管理员入口仍走本地哈希。
- 会话返回角色、菜单分区、登录方式与是否管理员；侧栏按「已启用模块 ∩ 角色菜单」渲染，未授权入口完全隐藏。
- 平台中心开放：用户管理、团队管理、角色管理、系统配置（`LDAP`）。
- 用户只能从`LDAP`目录添加，支持检索、批量授权角色、启用/停用/移除；本地`admin`不出现在用户列表。
- 角色为内置`algo`/`sre`，可改名、不可改菜单范围；平台中心仅管理员可访问。
- 团队支持新建/编辑、负责人与成员维护；队列模块未启用，关联队列入口完全隐藏。
- 系统配置保存`LDAP`连接参数，支持测试连接；本地用 Docker 提供模拟`LDAP`目录供检索、绑定与 E2E。
- **BREAKING**（仅权限与壳层）：算法工程师登录后不再进入数据中心；管理员侧栏将出现平台中心。现有`admin`/`admin123`与数据中心契约保持可用。

## Capabilities

### New Capabilities

- `ldap-directory`：`LDAP`配置保存、测试连接、目录检索，以及登录时的用户绑定。
- `platform-users`：平台可用用户的列表、从`LDAP`添加、角色授权、启停与移除。
- `platform-roles`：内置角色列表、改名，以及角色到菜单分区的映射。
- `platform-teams`：虚拟团队的创建、编辑、负责人与成员维护。
- `console-access`：按角色菜单与已启用模块控制侧栏、落地页和受保护 API。

### Modified Capabilities

- `admin-auth`：登录请求增加`mode`；`LDAP`用户可创建同一形态的服务端会话；会话 DTO 补充角色与菜单。
- `ops-console-shell`：管理员可见平台中心；`LDAP`登录可用；无可用模块时展示空态页。
- `datacenter-management`：数据中心接口仅对拥有运维中心菜单的会话开放（管理员与`SRE`）。

## Impact

- 后端：扩展`sys_user`，新增角色、团队、团队成员、`LDAP`配置表；新增用户/角色/团队/系统配置 API；认证接入`LDAP`客户端；权限中间件读取`g.Meta permission`。
- 前端：登录提交`mode`；壳层按菜单渲染；新增用户/团队/角色/系统配置页面；视觉继续对齐`prototype.v4`。
- 本地依赖：本机`PostgreSQL`不变；新增 Docker 模拟`LDAP`（默认`127.0.0.1:1389`）。
- 测试：认证/`LDAP`替身单元测试、用户/角色/团队服务测试、管理员与`LDAP`角色 E2E。
- `i18n`：不引入语言包，运行时文案用中文，与现有控制台一致。
- 数据权限：本迭代平台中心为管理员全局资源，不引入行级数据权限。
- 字典模块：本迭代不引入；状态/来源/角色编码用 Go 命名类型。
- 规则文件`.agents/rules/frontend-ui.md`、`.agents/rules/i18n.md`、`.agents/rules/data-permission.md`仍缺失，以前端原型、中文文案和「无行级数据权限」作为可验收来源。
