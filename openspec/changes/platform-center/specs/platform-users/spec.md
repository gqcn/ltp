## ADDED Requirements

### Requirement: 管理员可以分页筛选平台用户

系统 MUST 列出从`LDAP`加入的平台用户，支持关键词（姓名/账号/邮箱/部门）、角色与启用状态筛选，并在数据库侧分页。列表 MUST 批量投影角色名称、所属团队名称和最近登录时间，禁止对当前页循环查询。本地管理员账号 MUST NOT 出现在该列表中。

#### Scenario: 按角色筛选

- **WHEN** 管理员筛选角色为算法工程师
- **THEN** 返回的用户均具有该角色，且每条包含团队名称投影

#### Scenario: 本地管理员不在列表

- **WHEN** 管理员打开用户列表
- **THEN** 结果中不包含`admin`

### Requirement: 管理员可以从 LDAP 添加平台用户

系统 MUST 允许勾选目录中尚未加入的账号，指定统一角色后批量加入。已在列表中的账号 MUST 跳过且不报错中断整批。新用户默认启用，密码留空，登录走`LDAP bind`。

#### Scenario: 添加尚未加入的目录用户

- **WHEN** 管理员勾选一名未在平台中的目录用户并指定角色后提交
- **THEN** 该用户出现在平台用户列表中，状态为启用，角色为所选角色

#### Scenario: 已加入的用户不会重复创建

- **WHEN** 管理员提交的账号已在平台用户列表中
- **THEN** 系统跳过该账号，不创建重复行

### Requirement: 管理员可以启用、停用或移除平台用户

启停与移除 MUST 支持单条与批量。停用后该用户 MUST 无法`LDAP`登录，团队关系保留。移除 MUST 软删除用户并解除团队成员关系，允许之后再次从`LDAP`加入。不得移除当前登录用户。已是目标状态的用户 MUST 被跳过。

#### Scenario: 停用后无法登录

- **WHEN** 管理员停用`algo`后使用该账号尝试`LDAP`登录
- **THEN** 系统拒绝登录并提示账号已停用

#### Scenario: 不能移除自己

- **WHEN** 管理员尝试移除当前登录账号
- **THEN** 系统拒绝该操作

### Requirement: 管理员可以为用户授权角色

系统 MUST 允许为一名或多名平台用户指定内置角色`algo`或`sre`。授权后，用户下次读取会话时 MUST 反映新的菜单范围。

#### Scenario: 将用户改为 SRE

- **WHEN** 管理员把某算法工程师授权为`SRE`工程师
- **THEN** 该用户的角色编码变为`sre`，菜单包含训练中心与运维中心
