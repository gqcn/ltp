## Context

当前种子会写入标识`default`、`is_default=true`的数据中心，服务层禁止创建同标识、禁止停用/删除该行，列表 KPI 返回其简称。页面把它展示为始终可用的兜底。节点模块尚未实现，但文案已经假设未打标签的节点会落到默认中心。

约束：不改`001`旧迭代 SQL；节点/队列/集群表仍不存在，删除路径没有真实改挂逻辑。

## Goals / Non-Goals

**Goals:**

- 初始化后列表中不再出现内置默认数据中心。
- 所有数据中心同等对待：可启停、可软删除。
- 契约写明：节点没有`maip.io/datacenter`时保持未分配，不回落默认中心。
- 控制台去掉默认中心 KPI、角标和保护按钮。

**Non-Goals:**

- 不实现节点模块，不写入节点表。
- 不删除`ops_datacenter.is_default`列（避免本迭代`make dao`），新行继续写`false`。
- 不把已软删除的`default`行物理清除。

## Decisions

1. **用`003`软删除种子行，而不是改`001`**
   - 遵守 SQL 迭代文件规则，已有库可重复执行。
   - 备选是改`001`的`INSERT`：新库干净，旧库仍残留。拒绝。

2. **删除有关联时直接拒绝，不再改挂**
   - 本迭代关联计数恒为`0`，行为与现在一致（直接软删除）。
   - 节点接入后若存在关联，必须先解除或改挂到用户指定的数据中心，不得暗含默认中心。

3. **列表 KPI 去掉`defaultShortName`**
   - 前端改为三列：总数 / 已启用 / 已停用。
   - 备选是返回空字符串：页面仍留第四张卡。拒绝。

4. **标识`default`按普通标识处理**
   - 校验只保留格式规则。管理员若主动创建`default`，那是普通记录，无保护。

## Risks / Trade-offs

- [已部署环境仍看到默认中心] → `make db.init`执行`003`软删除；脚本按`code=default AND is_default AND deleted_at IS NULL`幂等更新。
- [有人依赖`defaultShortName`] → 本迭代前端同步删除字段，E2E 覆盖列表不再出现「默认数据中心」。
- [节点后续实现误加回落] → 规范明确未配置即为空，节点迭代不得再引入内置默认中心。

## Migration Plan

1. 提交`003-remove-default-datacenter.sql`。
2. 执行`make db.init`。
3. 发布去掉保护逻辑的前后端。
4. 回滚：恢复代码并（如需要）手工取消该行`deleted_at`；不自动重建默认中心。
