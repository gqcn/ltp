## ADDED Requirements

### Requirement: 开发机默认不申请 GPU

规划文档 MUST 将开发机定义为默认只申请`CPU`和内存的交互式工作空间，其工作负载不得声明或占用`GPU`资源；团队、资源队列或工作集群只用于现有权限、落点、存储以及通用资源约束，不得以可用`GPU`额度作为开发机启动条件。

#### Scenario: 启动开发机工作空间

- **WHEN** 算法工程师创建或重新启动开发机
- **THEN** 平台使用`GPU`请求为`0`的工作负载启动开发环境，不预留训练任务所需的卡数

### Requirement: CLI 创建独立训练任务

规划文档 MUST 要求训练命令行（`CLI`）在执行正式训练时向训练任务管理提交版本化任务规格并创建独立训练任务，由该任务重新选择或确认团队、资源队列和`GPU`规格；平台不得给运行中的开发机动态挂卡或将开发机原地转换为训练任务。

#### Scenario: 从开发机提交训练

- **WHEN** 用户在开发机中执行`aitrain job submit -f train.yaml`
- **THEN** 平台创建具有独立任务标识和生命周期的训练任务，并按`train.yaml`及现有队列规则申请`GPU`，开发机仍保持`GPU`请求为`0`

### Requirement: 开发环境与训练快照一致

规划文档 MUST 要求训练任务提交时固化镜像摘要、共享路径、外部数据引用、任务配置和资源规格，使训练任务不依赖开发机进程持续运行或未保存的本地状态。

#### Scenario: 提交后修改开发机内容

- **WHEN** 用户提交训练任务后继续修改开发机中的配置或停止开发机
- **THEN** 已提交训练任务继续使用提交时的不可变快照运行，不随开发机当前状态变化

### Requirement: 生命周期与资源计量分离

规划文档 MUST 将开发机和训练任务作为独立工作负载计量和管理；开发机的启动、停止、重启或闲置回收不得改变已提交训练任务的状态，训练任务的结束也不得关闭开发机。

#### Scenario: 训练期间停止开发机

- **WHEN** 独立训练任务已经排队或运行，用户停止其来源开发机
- **THEN** 平台只释放开发机的`CPU`、内存和会话资源，训练任务继续按自身生命周期与`GPU`计量运行

### Requirement: 开发机空闲回收不依赖 GPU 利用率

规划文档 MUST 保留开发机通用计算资源的空闲回收能力，但不得使用`GPU`利用率作为开发机空闲判定信号，也不得把空闲回收作为避免开发机长期占卡的主要机制。

#### Scenario: 开发机长时间无交互

- **WHEN** 开发机的终端和`JupyterLab`活动达到配置的空闲阈值
- **THEN** 平台按开发机规则回收其通用计算资源，且整个判定过程不依赖`GPU`利用率
