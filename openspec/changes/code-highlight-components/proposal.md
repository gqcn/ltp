## Why

控制台里凡是编写或展示源代码的地方，目前用普通`textarea`或自写正则着色，语言覆盖不全、深浅色不一致，也难跟上`YAML`/`JSON`/`Shell`的真实语法。需要换成主流、成熟的编辑与高亮组件，让编辑框和只读展示框共用同一套高亮。

## What Changes

- 新增控制台代码表面：可编辑的代码框与只读展示框都必须走共享组件，由成熟语法引擎负责分词与着色，禁止页面内自写高亮或无高亮的等宽`textarea`/`pre`。
- 替换现有代码编写入口：配置集文件编辑、新建任务启动命令与环境变量、接入集群的`Kubeconfig`。
- 替换现有代码展示入口：配置集文件查看、任务详情启动命令/环境变量/挂载快照、节点详情`YAML`、告警原始`JSON`。
- 深色/浅色主题下高亮色板跟随控制台主题；语言按文件扩展名或字段语义识别，并保留现有语言角标。
- 说明、备注、描述等自然语言字段，以及`Pod`进程日志，仍用现有控件，不纳入代码表面。

## Capabilities

### New Capabilities

- `console-code-surfaces`：控制台代码编辑框与只读展示框的共享组件、语言识别、主题跟随，以及现有编写/展示入口必须接入该组件。

### Modified Capabilities

无。现有`training-configs`、`training-jobs`、`cluster-management`、`node-management`、`alert-center`的业务契约不变，只改代码字段的呈现方式。

## Impact

- 仅前端：新增共享代码组件与依赖；改造配置、任务、集群、节点、告警相关页面；对齐现有`prototype.css`代码区外观。
- 不改`API`、数据库、后端校验与存储。
- 测试：更新任务详情对命令/环境变量高亮的`E2E`断言，并覆盖配置编辑、集群`Kubeconfig`、告警`JSON`等代码表面。
- 无`i18n`语言包；控件`aria`文案用中文（`.agents/rules/i18n.md`缺失）。
- `.agents/rules/frontend-ui.md`缺失，视觉对齐现有代码区样式与控制台深浅色变量。
- 架构/接口/后端/数据库规则无影响：不新增业务模块、不改模块启停、不改跨模块契约、不改`HTTP API`或`SQL`。
