## Context

`LTP`（大模型训练管理平台）仓库目前只有治理文件，没有可运行代码。需求来源是`prototype.v4`交互原型。原型覆盖训练中心、运维中心、平台中心共十余个页面，并依赖`Kubernetes`、`Volcano`、`LDAP`。本迭代只建立工程骨架，并用「数据中心管理」验证前后端闭环。

约束：

- 后端目录与分层遵循`GoFrame v2`与仓库`backend-go`规则：`api/`定义契约，`make ctrl`生成控制器骨架，`make dao`生成`DAO/DO/Entity`，业务实现放在`internal/service/`，禁止使用`logic/`目录。
- 数据库默认方言为`PostgreSQL`，SQL 必须幂等，时间字段交给框架维护。
- 前端样式框架使用`Tailwind CSS`。视觉语言以`prototype.v4`的`main.css`为唯一事实来源，不能只复用色板再用通用工具类重写按钮、表格、登录页和侧栏。
- `.agents/rules/frontend-ui.md`与`.agents/rules/i18n.md`缺失，本迭代以前端原型与中文文案作为可验收来源，不引入独立语言包。

## Goals / Non-Goals

**Goals:**

- 提供可本地启动的前后端工程、数据库初始化与代码生成入口。
- 本地管理员可以登录、保持会话、退出。
- 管理员可以完成数据中心的列表、新建、编辑、启停、删除，并看到默认数据中心保护。
- 未实现模块在前端完全隐藏，后端不暴露对应业务路由。

**Non-Goals:**

- 不实现`LDAP`、用户/团队/角色、队列、集群、节点、任务、配置集、实验分析、告警。
- 不接入真实`Kubernetes`或`Volcano`。
- 不引入字典模块、数据权限、多租户、插件框架。
- 不为后续模块预埋空页面或占位 API。

## Decisions

### 1. 单仓`GoFrame`根目录 + `web/`前端

选择在仓库根目录放置`GoFrame`后端（`api/`、`internal/`、`manifest/`、`hack/`、`main.go`），前端放在`web/`。这样`gf gen dao`、`gf gen ctrl`与`make dao`/`make ctrl`无需进入子目录，符合技能推荐的工程结构。

备选是`apps/backend` + `apps/frontend`。该结构适合多应用大仓，但会让`gf`命令与规则中的`make dao`路径变绕，本项目现阶段只有一个后端，不采用。

### 2. 首个业务模块选择数据中心

数据中心是队列、节点、任务的关联锚点，业务规则完整（默认中心、启停、删除迁移），但不依赖`K8s`。任务模块是产品核心，但依赖队列、团队、镜像与调度，无法独立闭环。

### 3. 认证采用服务端会话 Cookie，而不是`JWT`

登录成功后写入`HttpOnly`会话 Cookie，前端通过同源`Vite`代理访问`/api`。这样`E2E`与浏览器验证不需要手写`Authorization`头，也避免把令牌放到`localStorage`。

备选`JWT`更适合纯 API 客户端。本迭代只有浏览器控制台，会话 Cookie 更直接。`LDAP`后续可作为同一`auth`服务的另一种登录方式接入，不改变会话形态。

### 4. 数据中心以整数主键对外，`code`作为不可变业务标识

表`ops_datacenter`使用`BIGINT GENERATED ALWAYS AS IDENTITY`主键`id`，`code`（如`cq-lj`、`default`）是唯一业务标识，创建后不可改。API 路径使用整数`id`，列表同时返回`code`、`label`（`maip.io/datacenter=<code>`）。

这与`GoFrame`生成的`entity`、软删除、关联外键更一致。原型里把`code`当作`id`，前端展示仍使用「标识」列，不把内部数字主键暴露为运维同学日常输入。

### 5. 模块启停采用编译期装配，而不是运行时插件

本迭代只装配`auth`与`datacenter`服务。前端路由和侧栏由已启用模块清单驱动，未启用分区（训练中心、其余运维页、平台中心）完全不渲染。后端不为未实现模块注册路由。数据表保留，本迭代没有可禁用的已上线模块。

该方案比配置中心/插件宿主更简单。后续若需要运行时开关，再引入稳定的模块清单契约，而不是现在预埋抽象。

### 6. 枚举与字典

数据中心状态是布尔`enabled`，不是字典枚举。`labelKey`固定为`maip.io/datacenter`。因此本迭代不引入字典模块，也不在代码中硬编码业务状态字符串。过滤参数`enabled`使用布尔/`null`（不传表示全部）。

### 7. 关联统计与删除迁移

列表需要展示「节点 / 队列 / 集群」关联数。这些模块尚未实现，数据中心服务通过可选的`UsageCounter`接口查询；当前装配一个返回全零的实现，不循环调用不存在的详情接口。删除时若未来存在关联，将改挂到默认数据中心；当前无关联行，删除即软删除。

### 8. 前端选型

- `React 19` + `TypeScript` + `Vite`：单页控制台的主流组合。
- `Tailwind CSS v4`：需求指定的样式框架，用`@theme`映射原型色板。
- `React Router`：页面路由。
- `TanStack Query`：列表/详情请求、缓存与失效。
- `lucide-react`：线性图标，贴近原型 SVG。
- `sonner`：轻量 toast。
- 表格、表单、弹窗自行实现，不引入`Ant Design`/`shadcn`整套组件，以免视觉偏离原型。

### 9. 错误、日志与时间

- 业务错误使用精简版`pkg/bizerr`，各模块在`*_code.go`定义`bizerr.Code`。
- 日志只通过`pkg/logger`输出，并传递`ctx`。
- 响应时间字段转换为 Unix 毫秒时间戳。

### 10. 复杂度判断

不引入`Deps`聚合结构、全局服务定位、插件宿主或通用 CRUD 框架。`Controller`与`Service`均通过构造函数逐项注入。数据中心校验、默认保护、列表过滤都是直接控制流，不需要策略表或反射分发。

跨模块仅保留`UsageCounter`这一窄接口，因为关联统计是明确变化点（后续节点/队列/集群会上线）。当前零值实现避免列表`N+1`，也避免硬依赖未存在模块。

## Risks / Trade-offs

- [规则文件缺失] → 前端与`i18n`不以不存在的规则文件为准；任务与审查记录写明：视觉对齐原型，文案中文，无独立语言包。补齐规则文件后需回扫。
- [只用管理员账号] → 算法工程师/SRE 角色与菜单权限延后。壳层按「已启用模块」隐藏菜单，避免后续角色接入时出现空白入口。
- [关联数为零可能被误解为缺陷] → 列表「关联」列展示`0 节点 · 0 队列 · 0 集群`，交互上可接受；设计与页面说明这些模块尚未接入。
- [PostgreSQL 依赖] → 本地用`docker compose`启动；`make db.init`在库不可用时失败并给出明确命令，不静默改用`SQLite`。
- [默认数据中心种子与软删除冲突] → 使用部分唯一索引`WHERE deleted_at IS NULL`，种子用`code`子查询而不是写死自增`id`。

## Migration Plan

首次部署：启动`PostgreSQL` → `make db.init` → `make dao`（开发机）→ 启动后端与前端。种子写入管理员`admin/admin123`与默认数据中心。回滚即删除本迭代表或丢弃开发库，无线上数据。

## Open Questions

无阻塞问题。`LDAP`、集群、队列、任务留待用户确认首个闭环后再开后续变更。
