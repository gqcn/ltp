## Context

当前规划把训练平台描述为面向页面、命令行和外部系统的公共控制面，并为此规划统一开放接口、`Python SDK`、机器身份、项目级`RBAC`、数据脱敏和完整数据治理。这与当前产品形态不符：训练任务应在训练平台内部闭环，数据工程由第三方系统承担，平台也已经通过算法工程师、`SRE`工程师和平台管理员三类内置角色控制菜单与数据范围。

本次仅修订规划文档，不改变现有运行行为。规划总览当前包含用户尚未提交的其它修改，因此所有编辑必须基于工作区版本进行局部调整，不回退无关内容。

反馈复核确认，“训练数据引用”只在任务选择输入和提交快照时发生，不存在独立的数据对象治理、运行入口或生命周期；继续保留单独模块会让读者误判训练平台承担数据管理职责。同时，“任务提交与观测”只列举任务生命周期中的两个动作，不能稳定代表其实际覆盖的输入、配置、调度、运行、通知和日志能力。

## Goals / Non-Goals

**Goals:**

- 将治理模块限定为训练平台内部治理，并让模块名称、功能章节、排期和行业映射保持一致。
- 将数据工程明确交还第三方数据工程系统，训练平台仅消费可稳定引用的就绪数据。
- 将外部数据引用和任务快照并入训练任务管理，以稳定业务领域命名覆盖任务完整生命周期。
- 复用现有三类角色，不规划项目角色、临时授权或新的资源授权服务。
- 规划基础审计日志，以及任务、团队和项目维度的资源容量统计、使用监控和优化建议。

**Non-Goals:**

- 不设计对外开放接口、`Python SDK`、机器身份、服务账号或外部自动化接入。
- 不规划数据预览、清洗、脱敏、质量检查、授权治理、血缘、混合采样或漂移分析。
- 不新增角色、权限模型、配额审批、成本计费或自动资源调优能力。
- 不修改生产代码、接口、数据库、测试或现有运行权限。

## Decisions

### 治理模块以内部可追溯和资源治理为中心

将模块改名为“平台治理”，保留训练平台服务合并与功能回归，并只新增基础审计日志、资源容量与使用统计、资源使用监控和优化建议。相比保留“开放能力”但标注暂不建设，直接移除相关章节和排期能避免后续把公开接口、SDK 或服务身份误认为既定方向。

### 数据工程边界纳入训练任务管理

第三方系统负责数据获取、清洗、脱敏、质量、授权、版本和血缘；训练平台只在任务规格和运行快照中保存外部数据标识、版本及可挂载位置。“训练数据引用”没有独立运行入口、数据生命周期或跨模块服务契约，因此不再作为单独模块，而是并入训练任务管理的输入与快照职责。相比继续保留一个边界型模块，这一方式减少模块数量和重复说明，也不会让训练平台重新承担内容读取和治理责任。

### 任务模块采用稳定领域名称

将“任务提交与观测”改名为“训练任务管理”。新名称描述稳定的业务领域，而不是列举提交和观测两个动作；提交前校验、调度过程、训练进展、事件通知、列表摘要和日志定位继续作为内部能力，外部数据引用及任务快照作为任务输入能力置于首个子章节。此次调整只改变规划信息结构，不新增抽象、运行组件或跨模块调用。

### 权限完全复用现有内置角色

资源视图、审计查询和建议展示沿用算法工程师、`SRE`工程师和平台管理员现有权限与数据可见范围，不增加项目成员角色、对象级授权或临时权限。团队和项目只作为资源统计归属维度，不成为新的授权边界。

### 资源数据采用只读聚合

从现有调度和监控系统读取任务请求量、分配量、运行时长、利用率、排队和空闲等事实，按任务、团队、项目和时间窗口生成有界快照。页面和报表读取聚合结果，不按列表逐任务同步请求集群或监控系统。

### 优化建议不自动执行

建议基于可解释的确定性规则识别长时间空闲、申请量与实际使用偏差、持续低利用率和排队配置不合理等情况，展示证据、统计窗口和建议动作。平台不自动取消任务、缩减资源、调整队列或修改配额，避免治理建议扩大为自动控制面。

### 基础审计不扩展为合规平台

审计日志记录操作者、现有角色、时间、来源、动作、对象、请求追踪标识、结果和失败原因摘要，并支持有限条件检索。日志不保存训练数据正文、凭据、完整请求响应或外部数据工程系统操作，也不规划复杂审批、不可篡改存证或跨系统审计编排。

## Risks / Trade-offs

- [数据工程外置后，训练平台无法自行判断数据内容质量] → 由第三方系统提供稳定数据版本和必要摘要，训练平台只验证引用是否可解析和运行时是否可挂载。
- [不增加项目级权限会限制细粒度协作] → 接受该限制，继续使用已有角色、团队成员关系和现有数据范围，待出现明确业务缺口后再单独评估。
- [聚合快照存在延迟] → 在页面展示统计时间窗口和最近更新时间，资源准入仍以现有调度系统实时状态为准。
- [确定性规则可能产生不适用建议] → 展示规则依据与证据，只给出建议，不自动执行变更。
- [文档合并、重命名和顺延编号可能产生失效链接] → 更新`docs/平台规划/`内全部引用，并通过链接、标题、编号和关键词扫描验证。

## Migration Plan

1. 将任务模块更名为“训练任务管理”，把外部数据引用、任务快照和职责边界并入任务生命周期。
2. 删除独立数据引用模块，将后续模块编号顺延并更新全部文件标题和链接。
3. 更新规划总览中的核心对象、模块概览、功能排期、季度路线和行业映射。
4. 更新工作流等直接引用数据处理能力的章节，使其只消费第三方数据引用。
5. 扫描旧模块名、已删除功能名、失效编号和数据脱敏承诺，确认不存在残留规划。
6. 如需回退，仅恢复本变更涉及的文档段落和链接；不触碰同文件中的其它工作区修改。
